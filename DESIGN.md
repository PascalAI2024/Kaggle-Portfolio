# Kaggle Field Notes — GitHub-Native Art Direction

## Overview

This repository is a public, documentation-first research portfolio for competitive machine learning. It should feel **editorial, forensic, and optimistic**—like an excellent lab notebook opened after the work is mature enough to share. It must not feel like a startup landing page, a generic data-science README, or a leaderboard boast.

The public GitHub renderer is the canvas. The design uses hierarchy, typographic pacing, inline SVG, tables, Mermaid, callouts, details blocks, and deliberate absence. It does not require a website.

## Visual language

- **Core metaphor:** a field atlas / research room, not a product brochure.
- **Voice:** measured confidence; every claim has a receipt or stays visibly pending.
- **Primary visual:** compact, ink-blue research map with electric cyan evidence paths and violet boundary markers.
- **Typography:** GitHub’s native rendering. Use short uppercase labels, strong headings, and prose that earns its whitespace.

## Section grammar

1. **Masthead:** identity, promise, atlas visual, public-status badges.
2. **Navigation desk:** numbered reading paths that make the repository feel explored, not dumped.
3. **System diagram:** the learning loop, visibly centered on falsification and validation.
4. **Evidence surface:** a compact current-state table plus an explicitly labelled coverage chart.
5. **Research stations:** a mind map and paths into the deeper documents.
6. **Public contract:** boundaries as a confident editorial close.

Each supporting document begins with its role, contains one structural diagram or visual table, and ends with bidirectional navigation.

## Motion system

GitHub Markdown has no reliable motion surface. The equivalent is reading choreography: alternating dense diagrams with short declarative paragraphs, so a reader scans first and investigates second.

## Anti-defaults

- No fabricated scoreboards, synthetic ranks, placeholder “0” performance claims, or inflated outcome language.
- No enormous technology-logo wall or generic skills chart.
- No external web application, dark-dashboard cosplay, or documentation shaped like a marketing site.
- No raw private notebook, model, credential, active competition, or client material.

## Build rule

Any future public page reads this file and the [public boundary](PUBLIC_BOUNDARIES.md) first. Visual polish never outranks evidence.
